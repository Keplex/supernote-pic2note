# Pen, touch and preview processing — 1.0.1

All authored controls use useInputTarget: file/latest selection, presets, +/- adjustments, every tool and its caption, note return, language, About, license disclosure, and crop release. Normal finger interactions use RN Pressable/responders. Official PluginManager.registerMotionListener observes EMR toolType=2 as a fallback. Native screen pixels are divided by PixelRatio and matched to cached measureInWindow bounds; layout and scrolling refresh those bounds. Disabled buttons block crop hits underneath them. Button drags cancel, crop drags commit on release, and long-Undo restores the initial image. Matching native/RN release timestamps prevent double activation. Closing the UI, showing an error dialog or unmounting disables routing and unregisters the native motion listener, so a hidden editor cannot react to note-page input.

The image and tools occupy separate sibling areas. The toolbar uses a white surface with a black 1.5-dp outline and no shadow. Tall windows have a 64-dp column with wider gaps and end padding; shorter workspaces use 120-dp two-column or 176-dp three-column arrangements. The surface is centered within its own remaining-height area. Eight circular tools and the dock control have uniform gaps, with no groups or separators. Docking persists its side and layout callbacks refresh screen-space bounds.

Eight crop anchors share one continuous canvas gesture target, rather than separate moving hit targets. The image frame reserves an 18-dp inset; all 14-dp square markers remain within the canvas at full crop, with a 36-dp interaction area around each center. Closest-anchor hit testing handles tiny overlapping target regions and favors the active corner on ties. Tapping a marker only activates it; tapping elsewhere positions the active anchor. Corners move two adjacent edges. Top/bottom midpoint anchors move only the corresponding horizontal edge, ignoring x; left/right midpoint anchors move only the corresponding vertical edge, ignoring y. Edge centers are recomputed from the current crop, so they stay centered while other anchors move. Starting a drag on any marker activates it and preserves the grab offset. Coordinates are clamped to the full image; opposing edges cannot cross and retain the existing 2% minimum crop.

CropInteraction owns a snapshot per gesture. Each move publishes only a local overlay draft in CropCanvas; it does not change App recipe/history or call native processing. Release commits one final crop. Cancellation, closing, recipe/source change or relayout discards the draft. The preview Image source object remains stable while moving. Eight accessible anchor actions support activation without requiring an extra switch button.

InputRouter captures the canvas origin at contact, so moving markers or later bounds updates do not shift gesture coordinates. RN and native EMR streams share ownership and completion deduplication, including delayed full-gesture replays. Native EMR can take over a partial RN contact without another activation, so pen movement and release remain live even if RN reports only the initial contact. Button tap/hold routing remains separate and unchanged. Native drags can end outside the canvas; multi-pointer/cancel events discard the draft. Old corner-switch components, placement logic, labels and images are removed.

The preview draws one stable source image. Crop shade now uses non-overlapping filled rectangles: top and bottom span the canvas; left and right fill only the middle band. All share the same snapped physical-pixel edges as the dashed outline. The 0.9.4/0.9.5 border-ring shortcut was incorrect on Android: RN 0.79.2 BorderDrawable.drawRectangularBorders draws each same-color border as a full-length stroke, overlapping corners. With 75% white alpha, corners become 93.75% white while single-covered bands remain 75%, matching the reported cross-shaped shade. Filled backgrounds avoid that border path; no parent opacity or overlapping exterior fills are used. Export crop coordinates and pixels are unchanged. Regression checks sample uniform white alpha in all eight exterior regions and cut joins against black pixels, rather than checking only for dark leaks. Desktop raster tests do not prove Android/e-ink output.

The editor is no longer a ScrollView with a 510-dp minimum canvas. Presets and four tone controls form a non-shrinking block immediately below the file row, above the image. Only insertion actions stay at the lower edge. A flex:1/minHeight:0 workspace receives only the actual remaining height; its onLayout sizes the canvas and responsive toolbar without changing the image recipe or scheduling rendering. Every tone label, value and pair of 30×24-dp capsule +/- buttons shares one outlined group on a single line. Zero-sized pen bounds are explicitly invalidated during relayout, and an impossibly short toolbar is not allowed to leave invisible input targets over the bottom controls. About illustrates the same eight square anchors and uses the actual tool PNGs in read-only instructions; those examples register no input targets or edit callbacks.

Crop-only edits without auto levels reuse the current pixels immediately; export still uses the new crop bounds. PreviewQueue starts immediately with no debounce timer. Only one render runs; while busy only the newest pending recipe survives. Every recipe transition first invalidates the prior job's publication. This matters when undo returns to an already displayed recipe: no new render is needed, yet an earlier pending result must still be cancelled. A running native operation may finish, but its obsolete result/error cannot replace the current preview or leave insertion blocked.

Input always derives from source pixels, never from an adjusted preview. Native caches keep one decoded preview source (<=16 MB), one unadjusted resized frame (<=4 MB at the current preview limit), and parsed metadata. File path, size, modification time and geometry keys invalidate stale entries. Export decodes independently. For full-image auto levels, the histogram reuses the current unadjusted frame instead of repeating the same resample. A cropped auto-level region still gets its own source-based resampling to preserve its statistics. Unused histogram/statistic bridge data and non-auto-level histogram passes remain removed; previews do not fsync, while exported files still do. These changes reduce work but do not guarantee a particular wall-clock time on e-ink hardware.

Regression coverage includes an actual rendered-App scenario with a delayed native preview: brighten, undo before completion, then release the obsolete result. The original image must remain visible and insertion available. Input tests cover both event orders, duplicate suppression, disabled targets, drags, cancellation, long-Undo and closing. A layout simulation alone cannot establish firmware event coordinates.

Desktop tests simulate documented events; they cannot prove actual firmware coordinates, refresh behavior or input routing. These require a device test.

0.9.6 removes all post-replacement selection recovery and related bridge calls. Static preset keys are computed once, with one current-tone key per render instead of repeating both keys for each button. History appends to its bounded private stack rather than cloning it on every edit. The preview/export black/white-point resolution uses the existing shared helper. Source pixel caches, immediate latest-only preview processing, crop-only reuse and input deduplication remain unchanged. No device speedup is claimed without measurement.

White-mask output now maps final 240–255 gray levels to #FEFEFE after tone and inversion. The default/off path preserves all gray levels. Preview and export call the same ToneMath routine, with no extra image pass. Tests check the exact 239/240 boundary, all 256 levels, inversion order and in-place equivalence. This intentionally merges subtle near-white differences only when the mask toggle is on. The threshold is a chosen e-ink-friendly compromise, not a claim that every firmware quantizes highlights identically.

1.0.1 shares STEP_BUTTON_STYLE between editor controls and read-only About examples: 30×24 dp, radius 12. Inner group padding/gaps leave room for four inline groups. Anchor dragging uses the exact logical starting coordinate, while hit testing uses snapped display points, preventing parallel-only edge movement from introducing pixel-rounding drift.
